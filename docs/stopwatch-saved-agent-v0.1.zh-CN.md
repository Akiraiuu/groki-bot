# StopWatch C152：保存 Agent 固件 v0.1

本版在早期开发分支上改造设备接入。开发和编译结果以对应 PR 检查及本机验收记录为准；源码存在不等于已生成可刷固件，也不等于实机语音通过。

## 接入行为

- Grok 提供商改为从项目的 HTTPS 令牌服务获取临时凭证，每次重连重新请求。设备持有独立设备口令，长期 xAI Key 留在云端；不向设备再次填写 xAI Key。
- 短期令牌有效期优先相对于固定令牌服务经证书验证、HTTP 200 响应中的 UTC `Date` 检查，并保守扣除整次请求耗时，避免 RTC 时区/校时偏差误拒新令牌。无该响应头时仍用设备时钟；无效或重复响应头拒绝。保持 15～330 秒范围限制，不关闭 TLS 验证、不修改设备时钟；系统时间早于 2025 年时仍先等待校时。
- 连接 `wss://api.x.ai/v1/realtime?agent_id=...`。令牌响应必须提供有效的 Agent ID、匹配的 xAI 地址、版本号及接下来 15～330 秒内到期的令牌。HTTPS 证书验证和重定向拒绝开启。
- `session.update` 只设置音频输入/输出为 PCM16 单声道 24 kHz，不发送人设、音色、模型、工具或 VAD 覆盖。
- 首次会话确认可能仍是初始化数据。重复相同音频配置后，确认双向格式和采样率才开始采集；无法确认则报错恢复，不把错误采样率当成功。
- 按会话披露的工具清单识别原生 Web/X/文件搜索；Web/X 子函数由服务端执行，不向它们伪造函数结果。同名自定义函数优先视为客户端函数，不支持时明确失败。
- 现阶段沿用半双工和触摸打断。自然开口打断、AEC 及连续长时间运行仍待另行开发和实机验证。

早期通用 xAI 客户端路径保留协议回归测试，但设备的 Grok 配置入口只走保存 Agent + 云端令牌路径，不会回退到长期 Key 或通用模型。

## 设备设置

在设备 Wi-Fi 设置页选择 `xAI Grok Voice`，填独立设备访问口令，令牌服务 URL 留空即可使用本项目默认地址。该口令由本机云端配置程序生成并加密保存，后续可用本机工具传入设备。设置页只返回是否已配置，不返回口令内容。

原 `/api/xai-api-key` 以及旧 BLE xAI Key 写入特征停止接受长期 Key；批量设置表也已移除此字段。启动时对 NVS 中的旧 `xai_key` 执行逻辑删除，不再加载它。Wi-Fi 名称、密码和其他提供商配置保持原有字段。

本版先使用 Wi-Fi 设置页配置保存 Agent；BLE 页面会提示该入口，不提供长期 Key 输入。未来可扩展新的加密 BLE 设置特征，不能复用旧 Key 特征静默改变语义。

## 验证

主机测试使用生产 JSON 构造器、令牌解析、HTTPS 调用、音频客户端和设置注册表，仅替换 ESP 传输/RTOS。覆盖原有协议、保存 Agent 配置隔离、1920 字节 PCM 音频块、格式确认、原生工具和同名客户端工具、过期令牌、错误地址和 HTTP 重定向拒绝。

```sh
cmake -S components/conversation/test/host -B build-conversation-host
cmake --build build-conversation-host
ctest --test-dir build-conversation-host --output-on-failure
make build BOARD=stopwatch
```

需要 C++20、CMake、cJSON、mbedTLS 和 `tl_expected` 子模块；完整固件使用项目原有 ESP-IDF 5.5 工作流。固件不包含用户凭证，不能在 CI 中填入设备口令或 xAI Key。

刷写前仍需备齐 C152 恢复工具及恢复固件；当前设备备份可能包含旧配置，只在本机保存。构建产物为开发固件，板载麦克风、扬声器、头像显示、Wi-Fi 独立运行和重连行为必须逐项实测。
